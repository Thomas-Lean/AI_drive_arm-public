# ADR-004：舵机固件 V311 → V330 升级决定与执行流程

- 状态：**已接受**（签字：Thomas 2026-10-30；起草：审查方）
- 背景：
  - 7 颗舵机（ID 0–6）固件均为 V311，上位机显示型号均为 515、序号均为 10000001（2026-10-29 上位机扫描截图）。V311 不支持 0x16 数据监控、0x18 停止、0x19 同步，P0.4 的软急停两级兜底与 P1.1 同步下发都依赖这三条指令。
  - 厂家只提供 Windows 上位机升级；机身 Type-C 为出厂预留口、不对外开放（宇树官方答复）。已打通 B 方案：上位机 COM5 → com0com → COM12 → com2tcp `--ignore-dsr` → TCP <ARM_IP>:7777 → 臂上 bridge.py → /dev/ttyS4（2026-10-29 实测可扫描、读参数、导出参数）。
  - 7 颗舵机串在同一条总线上，线缆已胶死，无法单颗拆出；**无备件**。
  - 升级前参数已全部导出（`J0–J6_V311_20261029.usproj`）。分三组：J0–J2（功率 30000 / Kp 850 / 死区 3）、J3–J5（功率 20000 / Kp 800 / 死区 1）、J6（功率 12000 / Kp 800 / 死区 1）。J0–J2 与 J3–J6 为两款规格（Thomas 现场确认）。
  - 厂家（厂家技术支持，2026-10-29/30 微信）答复：
    1. 升级页列表中选中哪颗就只升哪颗；
    2. 升级后参数不变；
    3. 升级对时延无要求；
    4. 两款舵机用同一固件；
    5. 升级中不可断电，升级后需重新上电；零点不清；
    6. 330 兼容 0x01/0x08/0x0A/0x11。
  - 官方升级指南：https://fashionstar.com.cn/wiki/documents/servo/firmware-upgrade/（§3.4 升级后重新上电；§5 失败勿反复尝试，先联系技术支持）。
- 选项（各一行权衡）：
  1. **经 B 方案在臂上逐颗升级，每颗升完整臂重新上电并核验，再升下一颗**：可在第一颗异常时止损；代价是 7 次断电重启。
  2. 经 B 方案连续升完 7 颗，最后统一上电：省时；但违背官方「升级后重新上电」，且异常要到最后才发现。
  3. 不升级，留在 V311：零风险；但没有 0x16/0x18/0x19，软急停与同步下发方案作废，需另找替代。
- 决定：采用选项 1；**不使用「导入参数」功能**（厂家答复：导入后 ID 变 0，同总线会与 J0 冲突且无法分离）。
- 理由：厂家确认升级逐颗定点、参数保留、无时延要求，B 方案的主要不确定性已消除；逐颗核验把无备件条件下的最坏损失限制在一颗。

## 执行流程

**升级顺序**：J6 → J2 → J5 → J4 → J3 → J1 → J0。两款舵机各先升一颗验证（J6、J2），再升其余；J0 底座放最后。

**准备（一次）**
1. 臂上把 bridge.py 放到 `~/bridge.py`（`/tmp` 断电即清空）。
2. Windows：com0com 映射（CNCA0=COM5，CNCB0=COM12）保持不变。

**每颗循环**
1. 臂上：停 4 个服务 → `python3 ~/bridge.py`；Windows：`com2tcp --ignore-dsr \\.\COM12 <ARM_IP> 7777`。
2. 上位机：工具 → 舵机固件在线升级 → 密钥登录 → 更新页 → 扫描 → **选中目标 ID**，核对 ID 后点「开始更新」，等进度条完成，期间不碰任何东西。
3. 整臂断电，再上电。
4. 重复第 1 步，回到控制面板扫描。
5. 核验（全部满足才进入下一颗）：
   - 目标舵机版本 = V330，其余 6 颗仍在、ID 不变；
   - 目标舵机参数页再导出一份 `Jn_V330_<日期>.usproj`，由审查方与 V311 备份逐项比对，除文件头 Project ID 外一致。
6. 若参数有差异：用参数页该行的 → 按钮单项写回，**不用导入**；写回后再导出比对一次。

**立即停止条件**（停止后不做任何写入，截图交审查方与厂家）
- 进度条停住或提示失败（按官方 §5，不重试、不断电，先联系厂家技术支持）；
- 重新上电后少了舵机、出现重复 ID、或目标舵机仍为 V311；
- 参数差异项单项写回后仍不一致。

**全部完成后**
1. 恢复 4 个服务并确认 4 行 active。
2. 由 Thomas 用厂家原控制程序做一次小幅动作，确认整臂行为与升级前一致。
3. FACTS 登记：固件 V330、各颗升级日期、参数比对结果。

- 后果：
  - P0.4 解锁：0x16 探针、0x18 + 0x08 两级安全停止、TC-007（Q3 关卡）在 V330 上执行；V311 上已有的 P0.4 实测结论需在 V330 上复测关键项。
  - 每颗约 10 min（含断电重启），全程约 70–90 min【估算】。
  - 残余风险：无备件、无降级路径；任一颗变砖即阻塞项目，需向宇树或厂家购件。Thomas 接受。
- 何时重新审视：
  - 第一颗（J6）或第一颗 J0–J2 款（J2）出现任何停止条件；
  - 升级后宇树原控制程序行为异常；
  - V330 上 0x16/0x18/0x19 实测与厂家描述不符。
