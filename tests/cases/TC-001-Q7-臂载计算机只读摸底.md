# TC-001：Q7 臂载计算机只读摸底

- 目的 / 对应退出标准：关闭 §11 Q7 的摸底表部分——板卡/SoC 型号、/dev/ttyS4 占用者（4 个 marm 进程各自是否开串口）、GPIO 503 用途线索、Type-C 调试口枚举。产出「摸底表」，与 docs/ASSETS.md §4（as_deployed 拷贝件）共同构成 Q7 证据。
- 前置条件：臂上电、4 个 marm 服务正常运行（勿先停服务）；在上位机上 `ssh ubuntu@<ARM_IP>` 执行（先 `ip route get <ARM_IP>` 确认走 enp5s0，若走代理 TUN 先关代理，见草案 §00.8）。
- 安全注意：**全部命令只读**。特别禁止：`kill` 任何 marm 进程（服务 Restart=on-failure 会 5 s 内拉回，白折腾且留半开串口）；**禁止向 /sys/class/gpio/ 下任何文件 echo**（gpio503 疑似供电使能，写入可能瞬间断舵机电源导致坠臂）；禁止 reboot、禁止改任何配置文件。
- 执行人：Thomas

## 步骤

1. 在上位机上执行下方「一键采集块」，输出落盘 `arm_q7_survey_<日期>.txt`（命令原文与输出天然成对，符合 §6.1 证据规则）。

2. 检查输出补漏：
   - 一键块已用 `ssh -t` 为 sudo 分配终端，提示密码时直接输入（密码不会回显；如不便，也可先交互登录臂上手动执行块内三条 sudo 命令，再跑无 sudo 版）
   - `/proc/device-tree/model` 为空 → 补 `ls /proc/device-tree/ | head -30` 与 `sudo dmesg | grep -iE 'machine|model|board' | head -20`
   - `fuser` 无输出（无占用）与预期不符时 → 补 `sudo lsof /dev/ttyS4 2>/dev/null || echo lsof未安装`
   - C 段查 fd 不需要 sudo：4 个服务均为 `User=ubuntu`，Thomas 以 ubuntu 登录，读自己进程的 `/proc/<pid>/fd` 无权限问题

3. **Type-C 调试口枚举（可选，最后做）**：臂断电或保持上电均可，用 Type-C 线连接臂机身 Type-C 口 ↔ Mac；在 Mac 上执行 `system_profiler SPUSBDataType`（或系统信息 App → USB），记录新出现的设备（厂商/VID:PID/类名，如 USB 串口）。拔线复测一次确认对应关系。此步只接线和读 Mac 端信息，不动臂。

4. 把 `arm_q7_survey_<日期>.txt` 与 Type-C 记录（截图/文字）存 `tests/runs/<日期>-TC-001/`，执行方据此写 Q7 摸底表并关闭 §11 Q7。

### 一键采集块（上位机上执行）

```bash
ssh -t ubuntu@<ARM_IP> 'echo "===A 板卡/SoC===";
cat /proc/device-tree/model 2>/dev/null; echo;
head -25 /proc/cpuinfo;
echo "--cores/mem/disk--"; nproc; free -h; df -h /;
echo "--tty devices--"; ls -l /dev/ttyS* 2>/dev/null;
echo "--vendor clue dirs--"; ls -la /home/ubuntu/.extracted /home/ubuntu/.ota_system /home/ubuntu/.historical_data 2>/dev/null | head -30;
echo "===B 串口占用===";
sudo fuser -v /dev/ttyS4 2>&1;
echo "===C 4个marm进程（MainPID是autoStart*.sh的bash，二进制是其子进程，须再往下查一层）===";
for u in marm_controller marm_communication marm_control marm_subscripber; do
  p=$(systemctl show -p MainPID --value $u);
  echo "== $u MainPID=$p";
  ps -p $p -o pid,lstart,cmd --no-headers 2>/dev/null;
  echo "   exe=$(readlink /proc/$p/exe 2>/dev/null)";
  ls -l /proc/$p/fd 2>/dev/null | grep -i "ttyS" || echo "   (bash自身未打开ttyS*)";
  for c in $(pgrep -P $p); do
    echo "   -- 子进程 $c: $(readlink /proc/$c/exe 2>/dev/null)";
    ps -p $c -o pid,lstart,cmd --no-headers 2>/dev/null;
    ls -l /proc/$c/fd 2>/dev/null | grep -i "ttyS" || echo "      (未打开ttyS*)";
  done;
done;
echo "--services--"; systemctl is-active marm_controller marm_communication marm_control marm_subscripber;
echo "===D GPIO 503线索（只读）===";
ls /sys/class/gpio/ 2>/dev/null;
cat /sys/class/gpio/gpio503/direction /sys/class/gpio/gpio503/value 2>/dev/null;
ls -l /sys/class/gpio/gpio503/device 2>/dev/null;
sudo cat /sys/kernel/debug/gpio 2>/dev/null | head -60;
sudo dmesg 2>/dev/null | grep -iE "gpio|ttyS|uart" | head -30;
echo "--rc.local 引用--"; grep -rn "gpio\|503" /home/ubuntu/*.sh /etc/rc.local 2>/dev/null;
echo "===E 收尾==="; date; uname -a' 2>&1 | tee arm_q7_survey_$(date +%Y%m%d).txt
```

## 预期结果（可判定）

| 判定项 | 通过标准 |
|---|---|
| P1 板卡型号 | `/proc/device-tree/model` 或 dmesg 给出可登记的板卡/SoC 名称（若两者皆空，记录"型号不可知，仅 aarch64/4 核/1.9 GiB"，Q7 该子项按现有证据关闭） |
| P2 串口占用 | `fuser -v /dev/ttyS4` 列出进程清单；对照 C 段：预期**仅 marm_controller 服务下的 marm_controller_node 子进程打开 ttyS4**，其余 3 个服务的二进制不打开（源码已核实不引用串口，见 Q8 分析 §2 与 ASSETS §4）。注意 MainPID 是 autoStart*.sh 的 bash（脚本无 exec、Type=simple），**必须查子进程的 fd**，查 bash 自身会得出假阴性 |
| P3 GPIO 503 | direction=out、value=1；`/sys/class/gpio/gpio503/device` 或 debug/gpio 指明所属 gpiochip/控制器；rc.local 为唯一引用源。若线索指向供电使能，记录推断与依据，Q7 该子项关闭 |
| P4 Type-C | Mac 端记录到枚举设备名/VID:PID（或记录"无枚举"） |
| P5 全程只读 | 输出中无任何写操作命令；臂状态前后无变化（目视） |

- 判定：通过 / 失败 / 阻塞（阻塞 = 无法 ssh、sudo 不可用）
- 记录位置：`tests/runs/<日期>-TC-001/`
