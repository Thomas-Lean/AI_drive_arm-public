# TC-002：旧控制器停止 / 恢复演练（systemd 方式）

- 目的 / 对应退出标准：§11 Q7 关闭标准的后半句「停止/恢复旧控制器的命令（Thomas 演练一次）」；同时为 P0.4 单舵机实测铺路（先停官方控制器才可独占 /dev/ttyS4）。
- 前置条件：
  1. TC-001 已执行（已记录运行基线）
  2. 臂处于静止姿态，工作区无人无杂物；急停在手边（急停 = 断电，臂会下落，Thomas 实测无害，F27）
  3. 上位机侧无正在运行的示教器 / 驱动节点 / 正在下发的任务（有则先停——上位机侧操作由 Thomas 自行处置）
- 安全注意：
  1. **只能用 `systemctl stop/start`，不能 `kill`**。4 个服务均为 `Restart=on-failure`、`RestartSec=5s`（`arm_onboard/as_deployed/arm_services_20261028.txt`）：kill 后 systemd 会在 5 s 内重启进程，串口被夺回，测试无法进行。
  2. 停止控制器不会释放舵机锁力（源码无退出钩子），臂保持僵直；但**停止期间任何发给舵机的意外指令无 0x08 命令来源**，臂应完全静止——异常时按急停即可（急停 = 断电，臂会下落，实测无害，F27）。
  3. 意外断电 / 重启的自愈：4 个服务均 enabled，重启机器即恢复原状——这就是回滚保障，演练中不做 reboot。
  4. 注意第 4 个服务名是拼写 **marm_subscripber**（sic，服务商原文如此），少打一个 e 会报 unit not found。
- 执行人：Thomas（在上位机上 `ssh ubuntu@<ARM_IP>` 操作）

## 步骤

1. **停止**（一条命令，避免半停状态）：

   ```bash
   sudo systemctl stop marm_controller marm_communication marm_control marm_subscripber
   ```

2. **验证停止**：

   ```bash
   systemctl is-active marm_controller marm_communication marm_control marm_subscripber   # 应输出 4 行 inactive
   pgrep -af marm                                                                          # 应无输出
   sudo fuser -v /dev/ttyS4                                                                # 应无输出（串口已空闲）
   ```

   记录此刻臂的状态（应静止不动；俯视拍 10 s 视频备查）。

3. **保持 60 s**：观察臂是否保持静止、串口是否被任何进程重新打开（`sudo fuser -v /dev/ttyS4` 再查一次）。此步同时验证没有其他自启机制抢串口（§11 Q7 的「还有谁占用 /dev/ttyS4」反向证据）。

4. **恢复**：

   ```bash
   sudo systemctl start marm_controller marm_communication marm_control marm_subscripber
   sleep 2
   systemctl is-active marm_controller marm_communication marm_control marm_subscripber   # 应输出 4 行 active
   pgrep -af marm                                                                          # 应有 4 个进程
   systemctl is-enabled marm_controller marm_communication marm_control marm_subscripber  # 应输出 4 行 enabled（重启自愈保障仍在）
   ```

5. **（可选）功能回归**：在上位机上 `timeout 15 ros2 topic hz /current_servo_angle`，应看到 ≈9 Hz（8.98 Hz，F1）——确认控制器反馈通路恢复。ROS2 环境按旧项目惯例 source 后执行。

6. 全部命令与输出原文存 `tests/runs/<日期>-TC-002/`。

## 预期结果（可判定）

| 判定项 | 通过标准 |
|---|---|
| P1 停止生效 | 步骤 2 三条验证全过（4×inactive、无 marm 进程、ttyS4 空闲） |
| P2 静止保持 | 60 s 内臂无运动、ttyS4 仍空闲 |
| P3 恢复生效 | 步骤 4 验证全过（4×active、4 进程、4×enabled） |
| P4 功能回归（可选） | `/current_servo_angle` ≈9 Hz |

- 判定：通过 / 失败 / 阻塞（P1 或 P3 任一不过即失败，且失败时**不重试**，原文记录交回分析——可能存在第二个拉起机制）
- 记录位置：`tests/runs/<日期>-TC-002/`

## 备注：为 P0.4 预留

- P0.4 单舵机实测以本用例的停止步骤为前置；届时若只需腾出串口，最小集合仍是 4 个全停（其余 3 个不占串口，但 control/communication 订阅链在 controller 恢复前发消息可能堆积，一并停最干净）。
- 停止期间严禁 reboot：重启会把 4 个服务自动拉回并重新执行开机 6 连发 clearAngle（Q8 分析 §4）。
