## 步骤

1. **传脚本**（上位机上，进入本仓库工作区后；同名覆盖 10-28 旧版）：

   ```bash
   git pull
   ssh ubuntu@<ARM_IP> 'mkdir -p ~/p04_probes'
   scp tests/scripts/fsbus.py tests/scripts/fsbus_selftest.py tests/scripts/tc004_recon.py ubuntu@<ARM_IP>:~/p04_probes/
   ```

   通过标准：scp 无报错。

2. **停官方控制器并验证**（TC-002 步骤 1–2 原文，臂上执行）：

   ```bash
   sudo systemctl stop marm_controller marm_communication marm_control marm_subscripber
   systemctl is-active marm_controller marm_communication marm_control marm_subscripber   # 4 行 inactive
   pgrep -af marm                                                                          # 无输出
   sudo fuser -v /dev/ttyS4                                                               # 无输出
   ```

   通过标准：三条验证全过；臂保持静止（目视）。

3. **跑离线自检**（臂上，本轮必做——tc004_recon.py 已按 V330 版更新，须确认库与脚本无回归；不需要停服务但本轮已停）：

   ```bash
   cd ~/p04_probes && python3 fsbus_selftest.py
   ```

   通过标准：末行「结果：全部通过」（覆盖帧构造/收包解析/长度校验/同步集合判定/最小间隔/归一化/速度分析区分度/仿真舵机下 4 脚本主流程；任一 FAIL 即停，不开测）。

4. **运行侦察脚本**（臂上，输出文件名带时间戳防覆盖）：

   ```bash
   cd ~/p04_probes && python3 tc004_recon.py 2>&1 | tee tc004_输出_$(date +%Y%m%d_%H%M%S).txt
   ```

   运行约 20 s（帧间隔统一 ≥10ms，M4）。通过标准：无 Python 报错、末尾出现 `===== SUMMARY =====` 块；终端逐行可见 ping 结果与 0x16 解码行（电压/电流/温度/角度数值合理；每颗的电流/功率中位与 F40 参考值并列打印）。

5. **回传证据**（上位机上）：

   ```bash
   scp 'ubuntu@<ARM_IP>:~/p04_probes/tc004_*' .
   ```

   通过标准：`tc004_输出_*.txt` 与 `tc004_log_*.jsonl` 各一份到手（后续并入 `tests/runs/<日期>-TC-004/`；注意区分 10-28 V311 轮与本轮 V330 轮文件，臂上目录里两轮共存）。

6. **恢复 4 个服务并闭环**（臂上，TC-002 步骤 4 原文）：
