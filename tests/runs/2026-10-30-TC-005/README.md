## 3. 发现（写入 FACTS F45–F47）

1. **实测发出间隔被 rtt 钳制**：名义 ≤10ms 档（10/8/6/5/4/3ms）实际 s2s 全部 ≈12.0ms = rtt ~11ms + 总线空闲 ~1.8ms——请求-响应模式下单舵机连续查询的间隔物理下限 ≈ 事务耗时。A/B 零 miss 部分因此而来（更密间隔物理不可达）；厂家 5ms 口径（F38）指指令下发间隔、不含等待响应，与本数据不矛盾。→ 单舵机 0x16 连续查询上限 ≈83Hz。
2. **总线空闲实测下限**：0x16 事务间（上一响应帧→下一请求帧）gap 中位 1.76ms、min 0.55ms 下 1950/1950 成功——宽于 F14 建议（≥10ms）与 F38 厂家验证值（5ms）。单次轮观察，不作规范；设计仍按 ≥10ms。
3. **0x16 rtt 两态**：持续查询态 ~11ms（本轮 13 档全档 11.0–11.8，s2s≤12 与 >12ms 分箱无差异）vs 静息态 ~6ms（TC-004 宽松 150ms+ 间隔，F41）——状态切换的间隔阈值在 20–150ms 之间【未验证】。
4. **J5 双峰未复现**：TC-004 宽松下的 11.3–14.4ms 簇本轮消失（J5 全档中位 9.7–11.2，max 15.4 零星）——瞬态成因【未验证】。
5. **Q6 决议（按用例预定规则）**：7 轴收齐 p99=25ms → **40Hz（25ms 周期）处于边缘**（总耗时 >25ms 者 8/1000 ≈1%，最大 33.9ms），**20Hz（50ms）有充足余量**；P1.2 目标 ≥10Hz，「收齐 + 同步下发帧 + 守卫」预算充足 → **Q6=「后置」（结论不变）**。
