# Joy-Con 遥操作实机验收清单（约 15 分钟）

> 交付对象：实机操作人。前提：[`sdk/实机验收清单.md`](../../sdk/实机验收清单.md) 已通过
> （舵机固件 V330、方向检查做过、臂上 `d1t_arm_ctrl` 已按 [`deploy/实机部署.md`](../../deploy/实机部署.md)
> 起好）；本清单只验 Joy-Con 遥操作这一层。命令在仓库根目录原样可抄；fish 终端先 `bash`。
>
> ⚠ 两项首验内容：**流式带 J6 目标（j6_deg）**是 SDK 未做实机验收的功能
> （`sdk/README.md` 已知限制 #8）；**流式中 J6 按控制器轴限速 100°/s 运动**
> （比 `gripper()` 的 20°/s 快 5 倍），第 3 步留意手指。
> 全程物理急停在手边；本仓库不对实机使用后果负责（见 LICENSE）。

## 0. 手柄配对与依赖（约 5 分钟，一次）

1. **Joy-Con 配对**：手柄滑轨内侧小圆点（同步键）按住约 3 s 进配对模式 →
   Ubuntu 系统设置 → 蓝牙 → 配对 "Joy-Con (R)"。之后单手柄模式：按住 **R + ZR** 3 s，
   震动即绑定（详见 joycon-robotics README）。后续重连：按一下 R 等震动，再按住 R+ZR。
   检查：`bluetoothctl devices` 能列出 Joy-Con。
2. **装 joycon-robotics**（不在 PyPI，源码装；Ubuntu 22.04）：
   ```bash
   sudo apt-get install -y dkms libevdev-dev libudev-dev cmake git
   git clone https://github.com/box2ai-robotics/joycon-robotics.git ~/joycon-robotics
   cd ~/joycon-robotics && pip3 install --user -e . && make install
   ```
   通过判据：`python3 -c "from joyconrobotics import JoyconRobotics; print('ok')"` 打印 ok。
3. **通信环境**（每个新终端都要；`<HOST_IFACE>` = 上位机接臂网卡名，`ip addr` 查）：
   ```bash
   cd ~/AI_drive_arm-public-jc && source deploy/env.sh real <HOST_IFACE>
   python3 -m d1t_sdk ping
   ```
   通过判据：`online:` 七个 True。不过不往下走。

## 1. 预演 `--dry-run`（约 2 分钟，只读不发流）

命令（终端保持 source 过 env.sh）：

```bash
python3 apps/joycon_teleop/joycon_teleop.py --side right --dry-run
```

操作：按提示**先松开 A 再按住**接管；转手腕、推摇杆（映射表见 `apps/joycon_teleop/README.md`）。

| 判据 | 通过标准 |
|---|---|
| 接管 | 打印 `Engaged at measured TCP [...]`，与 `python3 -m d1t_sdk state` 的 tcp.pos 一致（±1 cm） |
| 预演 | 每 0.5 s 打印 `Preview pos(m) … q(deg) …`；转手腕 → q 连续变化；摇杆纵向推 → pos 沿工具 X 变化 |
| 只读 | 臂全程不动（含 J6）；`state` 的 mode 保持 IDLE/HOLD、fault=0 |

中止：Y 或 Ctrl-C（无运动，无风险）。

## 2. 低速接管（约 3 分钟）

```bash
python3 apps/joycon_teleop/joycon_teleop.py --side right --speed-mps 0.02 --angular-dps 10
```

| 判据 | 通过标准 |
|---|---|
| 接管不动 | 按住 A 瞬间臂原位保持（首帧发实测角） |
| 跟随 | 末端以低速（≤0.02 m/s）跟随手腕姿态；摇杆纵/横移、R/摇杆按下升降方向与 README 映射表一致 |
| 停住 | 松开 A → 臂 1 s 内完全静止（HOLD） |
| 无故障 | `fault=0`；平移（摇杆/升降）不应出现 `Holding:`；**持续快速转手腕会出现成串 `Holding:`（限幅保持，属算法设计行为，输入放缓即恢复，见 README 已知限制 #2）——若此现象影响操作手感，记下场景与参数** |

中止手段：**松开 A（最快）**；Ctrl-C / Y 退出（看门狗约 0.3 s 停臂）；物理急停兜底。

## 3. 夹爪（约 3 分钟，接上一步不退出）

操作：按住 A 期间按 **ZR** 切换夹爪（合拢 10 mm ↔ 张开 55 mm），空夹与夹物各试一次。

| 判据 | 通过标准 |
|---|---|
| 空夹合拢 | 指间距到 ≈10 mm（金属面），张开回 ≈55 mm |
| 夹住物体 | 合拢途中被物体顶住后停住，打印 `Gripper stalled at … mm; freezing J6 command`（守卫生效，J6 不长时间堵转） |
| 速度 | J6 开合明显快于 `python3 -m d1t_sdk gripper`（流式 100°/s 轴限速，首验留意手指） |

中止：松开 A；Ctrl-C。

## 4. 松开停臂与收尾

| 判据 | 通过标准 |
|---|---|
| 停臂 | 松开 A 后 `python3 -m d1t_sdk state`：mode=HOLD、fault=0、q_deg 与目视姿态一致 |

收尾：脚本 Y/Ctrl-C 退出 → `python3 -m d1t_sdk lock` → 按需回原厂
（[`sdk/实机验收清单.md`](../../sdk/实机验收清单.md) §2）。

## 5. 故障口径

脚本自动退出（退出码非 0 + 一行原因）的触发条件：手柄 HID 报告停更 >0.25 s（蓝牙断连）、
反馈停更 >0.5 s、控制器 fault≠0、任一舵机离线、跟随偏差 >18°。恢复：
`python3 -m d1t_sdk reset`（ESTOP/FAULT 后必需）→ 重跑第 1 步起。

## 已知限制（验收时留意）

- FK/IK 绝对精度 ±1 cm 量级（零偏未精标、重力下沉 SDK 不补偿）；遥操作看的是相对跟随，不卡绝对位置。
- 接管时若 J4（原脚本称 J5）已在 ±85° 余量区（`--j5-margin-deg 5`），只允许向内退。
- 夹持力仍靠舵机自保护（P=0）+ 控制器温度守卫（45 ℃ 降出力 / 50 ℃ 释放）；守卫冻结角后夹持力约等于冻结瞬间的保持力。
