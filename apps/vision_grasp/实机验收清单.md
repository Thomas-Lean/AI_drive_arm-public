# vision_grasp 实机验收清单（约 40 分钟）

> 交付物：`apps/vision_grasp/`（手眼标定 + YOLO 抓取）。离线测试与 `--sim` 仿真
> dry-run 已全过；本清单验的是「上真机能标定、能抓」。按顺序做，**每步过了再往下**。
> 命令原样可抄；`<HOST_IFACE>` = 上位机接臂网线的网卡名（`ip addr` 查）；
> fish 终端先 `bash`。

## 0. 准备（约 10 分钟）

1. **臂侧**：控制器已在臂上运行（按 `deploy/实机部署.md`；首次部署必须先做
   `sdk/实机验收清单.md` 的方向检查与零位米尺复核——标定精度直接吃零位误差）。
2. **相机**：D435i 固定在臂末端（刚性，眼在手上），USB 接上位机；标定板
   ArUco（`DICT_4X4_50`、id 0、边长按 `config/default.yaml` 的
   `marker_length_m` **实测黑框外沿**）压平贴在工作台硬背板上。
3. **上位机环境**（每步前的两个终端动作）：
   ```bash
   cd <仓库根>
   source deploy/env.sh real <HOST_IFACE>
   ```
   Python 依赖按 `apps/vision_grasp/requirements.txt`（`opencv-python==4.7.0.72`
   要 Python 3.10–3.11；系统 cv2 版本旧时建 venv：`python3 -m venv --system-site-packages
   ~/vg-venv && ~/vg-venv/bin/pip install opencv-python==4.7.0.72`，之后命令里的
   `python3` 换 `~/vg-venv/bin/python`）。
4. **YOLO 权重**：下载到 `apps/vision_grasp/models/`（见 `apps/vision_grasp/models/README.md`）。
5. **通信检查**（不过不往下走）：`python3 -m d1t_sdk state`
   → 通过判据：mode=IDLE/HOLD、online 七个 True。
6. **常用处置**（全程适用）：
   - 中止脚本 = 发送端 **Ctrl-C**（看门狗约 0.3 s 停臂）；来不及按**物理急停**。
   - 报 `Unexpected robot state: IDLE estop` 或 `motion refused: latched …`：
     这是急停/故障**锁存**（适配层只自动清脚本自己发的急停；外部急停与 FAULT
     一律拒绝运动）。处置顺序：先看现场为什么锁存（谁按了急停？`python3 -m
     d1t_sdk state` 看 fault 位），**确认安全后** `python3 -m d1t_sdk reset` 清掉再跑。

## 1. 取景（约 2 分钟，不动臂）

```bash
python3 apps/vision_grasp/scripts/live_view.py
```

- 通过判据：窗口出图、颜色/曝光稳定不闪烁、分辨率 1280×720@30；把标记放在
  工作台预放物体的位置，画面里标记完整、边长 ≥ 60 px。
- 中止：q / ESC / 关窗（纯显示，无运动）。
- 不过：查 USB / `lsusb | grep -i intel` / udev 规则（`apps/vision_grasp/README.md` 依赖节）。

## 2. 点位彩排（约 5 分钟，动臂 32 个采集位）

```bash
python3 apps/vision_grasp/scripts/pose_test.py --dwell 2
```

- 通过判据：32/32 点走完无 fault；每点 `hold drift` ≤ 1°（个别点自激抖动 →
  记下点位，从 `config/default.yaml` 的 `poses_deg` 里删掉它再跑，凑不够 15 个
  就手填替补点，注意 J5 正负两侧都要有、J2 ≤ 89°）。
- 中止：Ctrl-C（不发自动回安全位；臂停在当前点，HOLD 保持）。
- 首选先做过仿真 dry-run（`--sim` 控制器上 `python3 apps/vision_grasp/scripts/dryrun.py`）。

## 3. 手眼标定采集与求解（约 15 分钟/板型，动臂）

**前置：用尺实测板子并填进 `config/default.yaml`**（打印会缩放，标称值不可直接用）：
单 ArUco 量黑框外沿边长填 `marker_length_m`；ChArUco 量格边填 `square_length_m`、
marker 边填 `marker_length_m`。板压平贴硬背板。

```bash
python3 apps/vision_grasp/handeye.py
```

- 通过判据：逐点走完 → 回安全位 → 终端打印 `Quality: ... ` 且含
  `"qualified"`，最后 `Saved: .../config/hand_eye[_charuco].npz`；`T_tcp_camera`
  平移分量量级 ~几 cm、旋转合理（相机相对法兰的安装姿态）。
- 中止：Ctrl-C → **不自动回安全位**，臂停在当前点；确认无碍后手动
  `python3 -m d1t_sdk joint 0,-90,89,0,0,0` 回安全位（或重新 home）。
- 常见拒收（日志会写原因，全流程仍会继续）：标记不可见/太偏、采图期间漂移、
  点位重复。全部点被拒 → 先解决标记可见性（贴平、光照、点位改近一些）。
- 不合格不要硬用：调整点位（多样性不足）或检查标记是否贴平（平面标记弱深度轴，
  10% 视在尺寸偏差 ≈ 5 cm 深度误差）后**重新采集**；离线重算只用于换解法参数：
  `python3 apps/vision_grasp/handeye.py --solve apps/vision_grasp/config/sessions/<时间>/samples.npz`。

### 3b. 板型对比（同臂同点位做两轮）

> 公平对比：**同一台臂、同一组 `poses_deg`、同一相机**，先 ChArUco 标一次，
> 再把工作台上的板换成单 ArUco 标一次（约多 15 分钟）。两轮之间只改 board 段：

| 轮次 | `board.kind` | `marker_length_m` | 其他 | 产出 |
|---|---|---|---|---|
| 1 | `charuco` | ChArUco marker 边实测值 | 格数/格边实测值 | `hand_eye_charuco.npz` |
| 2 | `aruco` | 单标记黑框外沿实测值 | `marker_id` | `hand_eye.npz` |

两份 `Quality` 输出（平移/旋转 RMS、最大误差、留出验证）**并排抄进实测记录**。
两文件互不覆盖；`yolo_detect`/`grasp_yolo` 读哪份由 `--config` 指向的配置的
`board.kind` 决定：`config/charuco.yaml` → `hand_eye_charuco.npz`，不带 `--config`
（默认 `default.yaml`）→ `hand_eye.npz`。两份解不一致时用尺量板角位置仲裁
（README 已知限制 #13），本臂实测以 ChArUco 为准，第 4、5 步因此都带
`--config .../charuco.yaml`。原工程的单 ArUco 记录不在本仓库、且是另一台
臂，只能参考，不直接比。

## 4. YOLO 检测看坐标（约 3 分钟，不动臂）

```bash
python3 apps/vision_grasp/yolo_detect.py --config apps/vision_grasp/config/charuco.yaml
```

- 通过判据：绿框 + 类别/置信度；`CAM` 行有相机系坐标；标定文件加载后还有
  `BAS` 行（基座系）。**判据核心**：同一个物体放两个不同位置，BAS 坐标与
  实测摆放位置差在 ~1–2 cm 内（标定质量的抽查；差 5 cm+ → 重标）。
- 中止：q / ESC（纯检测，臂不动；模型首次加载 CPU 上要几十秒，属正常）。
- 零检测：yoloe 下 `classes` 白名单不能为空；文本编码器缺失首次会下载 ~240 MB。

## 5. YOLO 抓瓶（约 10 分钟，动臂）

```bash
# 首次必用 dry-run：只取景+预检（IK/J5 余量/闭口），不动臂
python3 apps/vision_grasp/grasp_yolo.py --config apps/vision_grasp/config/charuco.yaml --dry-run
# 确认目标选择合理后再实抓
python3 apps/vision_grasp/grasp_yolo.py --config apps/vision_grasp/config/charuco.yaml
```

- 通过判据（`--dry-run`）：目标框稳定选中矿泉水瓶/握力球，日志里
  `Pregrasp ... final motion=linear` 与 `Grasp ... close XXmm` 数值合理
  （close 只是闭合上限：实测爪宽 × 0.7，钳在 [15, 张口] 内）。
- 通过判据（实抓）：按 `g` → 预抓取 → 直线接近 → 闭爪并锁停住角（日志
  `Closing gripper ... (cap only; locks at the stopped angle)` →
  `Holding at the stopped angle: XXmm`）→ 原路退出回 ready；按 `q` 松爪回
  安全位退出。
- 闭爪自保（自动，不需操作）：闭住后若 2 s 内开度不稳定（`Gripper did not
  settle`）或空夹（`nothing held`，开度 ≤ 15+2 mm），脚本自动**开爪并退出**，
  不进入保持——此时查检测目标是否还在、爪宽测量是否偏小，再重试。
- 中止：窗口内 **q**（开爪+回安全位）；Ctrl-C（看门狗停臂，物体可能还在爪里）；
  异常立即物理急停。直线段失败会停在该次流程，不自动换关节运动重试。
- 首抓 90° 错位（爪开合方向不对）→ 改 `grasp.open_axis: z` 再试；
  到位太深/太浅 → 调 `grasp.grasp_offset_m`（正值外退）。
- 安全红线：`min_base_z_m` 别低于工作面；夹爪连抓多轮摸一下温度
  （45 ℃ 控制器自动降出力、50 ℃ 释放，是保护不是日程表）。

## 收尾

```bash
python3 -m d1t_sdk joint 0,-90,89,0,0,0   # 回安全位（J2=89°，见已知限制）
```

标定产物在 `apps/vision_grasp/config/hand_eye.npz` 与 `config/sessions/<时间>/`；
换支架/工具/重装相机后必须重标。跑完把结果（成功/失败现象、drift、BAS 抽查差值）
记回本清单同目录，供下次整定。
