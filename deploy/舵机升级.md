# 舵机升级（V311 → V330）

7 颗舵机（ID 0–6）出厂固件 V311 不支持 0x16 数据监控、0x18 停止、0x19 同步；
软急停与同步下发依赖这三条指令，必须升到 V330。官方指南：
<https://fashionstar.com.cn/wiki/documents/servo/firmware-upgrade/>（先通读：§3.4 升级后重新上电；
§5 失败勿反复尝试，先联系技术支持）。

**红线（先记住再动手）**

- 升级过程中**绝对不能断电**，断电即变砖。全臂无备件、线缆胶死无法单颗拆出。
- 升级页选中哪颗就只升哪颗；一颗升完 → 整臂断电重新上电 → 核验通过 → 再升下一颗。
- **不使用「导入参数」功能**：导入后 ID 变 0，同总线会与 J0 冲突且无法分离；
  参数一致性靠升级前后各导出一份参数文件人工比对。
- 升级后零点不清（厂家答复），但建议重置一次圈数。

## 1. 通路准备（B 方案：Windows 上位机经网线访问臂上总线）

```
Windows 上位机 COM5 ⇄ com0com 虚拟串口对 ⇄ COM12 ⇄ com2tcp ⇄ 网线 ⇄ 臂 192.168.123.100:7777 ⇄ 臂上 ~/bridge.py ⇄ /dev/ttyS4 ⇄ 舵机总线
```

| 环节 | 做法 | 注意 |
|---|---|---|
| Windows 网卡 | 静态 IP 192.168.123.51/24 | 与臂同网段 |
| com0com | **签名版**驱动；`change CNCA0 PortName=COM5`，CNCB0 保持 COM12 | 未签名版报 0xE000022F；com0com 端口不在 Ports 类，上位机看不到 → 按 ReadMe FAQ 用 hdwwiz 添加一个「标准通信端口」COM5 并禁用，再把 CNCA0 改名为 COM5 |
| com2tcp | `.\com2tcp.exe --ignore-dsr \\.\COM12 192.168.123.100 7777` | 不加 `--ignore-dsr` 会一直等 DSR，连不上 |
| 臂上 bridge | 先停 4 服务，再 `python3 ~/bridge.py` | `/tmp` 断电即清空，脚本必须放 `~/`；ttyS4 只能一个进程用 |

验证通路：上位机扫描总线，能看到 7 颗（型号 515）即通。

## 2. 升级前留底

1. 上位机逐颗导出参数，7 份 `.usproj` 存好（后续比对基准）。
2. 记录每颗固件版本（V311）。

## 3. 逐颗升级

顺序：**J6 → J2 → J5 → J4 → J3 → J1 → J0**（两款舵机各先升一颗验证——J6、J2 是不同规格；
J0 是底座放最后）。

每颗五步：

1. 升级页只勾选这一颗，升固件；
2. 升完**整臂断电 → 重新上电**（官方要求）；
3. 重走 §1 通路（上电后官方服务会自启，需重新停 4 服务再起 bridge）；
4. 核验：上位机扫描 7 颗都在、该颗固件显示 V330、读参数正常；
5. 该颗再导出一次参数，与留底逐项比对（应 25 项全一致）。

全部通过才升下一颗。

## 4. 收尾核验

1. 7 颗全部 V330，参数比对全部一致；
2. 重置一次圈数（0x18 释放 → 0x11）；
3. 恢复 4 服务（4 行 active）；
4. 读角度 / 温度 / 电压正常（0x16 在 V330 下才可用，能读到即证明升级生效）。

## 5. 出问题怎么办

| 现象 | 处置 |
|---|---|
| 升级中途断电（舵机无响应/灯异常） | 联系厂家技术支持，勿反复尝试重刷（官方指南 §5） |
| com2tcp 连不上 | 确认 `--ignore-dsr`；臂侧 bridge.py 活着、4 服务已停 |
| 上位机看不到 COM5 | com0com 未签名版或端口没按 FAQ 加「标准通信端口」并禁用 |
| 升级后某颗读不到 | 断电重新上电再看；仍不行按变砖预案联系厂家 |
| 导入参数后总线上出现 ID=0 | 立即断电解耦：该颗 ID 已被覆盖成 0，只能单独接出来重设 ID——所以禁止导入 |
